# internal/profile

The profile store: location, strict validation, resolution, and atomic writes of the profile configuration v1. The contract is `.ai/specs/2026-11-12-profile-config.md`; the requirements are in `.ai/specs/capabilities/profile-config.md`. Every change here is `risk-high` (identity selection and a shared contract, `SDLC.md`).

- **Provider-agnostic.** This package imports no provider package, not even `internal/provider`, so that adapters can import it without a cycle (ADR #35). Nothing here names a forge: no `github`, no host, no token prefix. A provider owns its block through `SettingsValidator`; the composition root registers it with its token prefixes in a `Registry`.
- **Adapter contract.** `ValidateSettings` gets the host (syntax already checked) and a block that is an object, duplicate-free, and secret-scanned. Its errors come from `Errorf` with `ErrConfigInvalid`, `ErrUnsupportedHost`, `ErrUnsupportedKeyReference`, or `ErrInlineSecret`, start with a path relative to the profile (`host: …`, `<provider>.<member>: …`), and echo values only through `Quote`. The core prefixes `profiles.<name>.` and keeps only the text and that class; any other class becomes `ErrConfigInvalid`, so an adapter can never signal "file missing" (only the unexported `errMissing` lets `Write` start from an empty configuration). Key references are parsed with `ParseKeyRef`.
- **Strict.** Unknown members, duplicate members at any depth, wrong JSON types, and any version but the integer `1` are errors. Do not relax a rule to accept a file: a silently ignored member changes which credential an agent gets. A change to the schema, including a new optional member, increases `Version` and adds an in-memory migration; a new provider does not.
- **Error order** is part of the contract: syntax and size, inline secrets, duplicates, version, top level, then profiles in document order (core members before the provider block).
- **No secret echo.** The inline-secret scan runs over every string and member name, unregistered provider blocks included, before any other rule, and its error names the path only. Echo a value only for profile names, provider names, hosts, and adapter-chosen identifiers, and only through `Quote`/`sanitize`. Never log or print the raw document.
- **Pure validation.** `Parse` touches no file system and no network (`ARCHITECTURE.md`, dependency rule 5). `Path` reads the environment only through the `getenv` it receives.
- **File rules.** `Load` opens without blocking, refuses anything but a regular file, and refuses the file or any directory of its symlink chain that another user owns or that group or others can write. `Write` takes `flock` on `<file>.lock` next to the file it replaces (the symlink's target when the path is a symlink, so every path to one file takes one lock), refuses to write when the symlink changed while it waited, validates the result with `Parse`, writes a `0600` temporary file, syncs, and renames it; when only the directory sync after the rename fails, the error says the change was written but may not survive a crash; the directory is tightened to `0700`; a dangling symlink is refused, a symlink's target is replaced and the link kept. Reads never write. Profiles of unregistered providers survive a write unchanged.
- **Tests** call `testenv.Isolate(t)` first and use the fake `acme` provider of `helpers_test.go`, never a real forge. Every rule has a hostile-input row; secret tests assert the value never appears in the error.

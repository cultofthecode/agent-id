# internal/activation

The child environment of an agent context and the `exec` slice (`internal/activation/exec`). Spec: `.ai/specs/2026-11-13-exec-child-environment.md` (#20, #68); requirements in `.ai/specs/capabilities/exec.md`. Every change here is `risk-high`: it decides what credentials a started agent can reach, and the variable names and exit codes are a shared contract.

- **Fail closed, from the first merge.** The plan always carries the neutral credential baseline: empty `credential.helper`, `http.https://<host>/.extraHeader` and `core.askPass`; `GIT_TERMINAL_PROMPT=0`; `GIT_ASKPASS` and `SSH_ASKPASS` dropped; the provider's credential variables dropped and its non-secret decoys set; an empty agent-id-owned CLI configuration directory; the launcher of the CLI first on `PATH` (`LauncherScript`: it starts `agent-id cli <binary>`, which is the `gh` shim of #23; without the agent-id binary it refuses with exit 125). An empty drop list is `ErrPlanUnsafe`. Later stories replace entries with the bot's; they never remove the baseline.
- **No token in the environment.** `exec` injects no App token. The `gh` shim (#23, `internal/cliint`) adds the token for one `gh` call only, and the Git credential helper of #22 mints at use, so no token enters the environment. `Build` rejects a value with a token prefix, a PEM marker, a JWT shape, a newline, or a NUL.
- **Names no forge.** The provider supplies hosts, variables, prefixes and the neutral CLI through `provider.Activator`; never import an adapter. The activator reads no key and makes no request.
- **Pure decisions.** `ReadContext`, `Decide`, `CheckInheritedGit`, `ParseGitConfigParameters`, `Build`, `ClassifyRemoteURL`, `HasPassword`, `RewritesToSSH`, `EffectiveHeaders`, `NetrcHosts` have table tests with hostile input. `Build` is idempotent and append-only for `GIT_CONFIG_*`.
- **Messages** name a variable, a key section (never the URL subsection), a path, or a remote; never a value, a URL's user-info, or a header value. `failf` keeps messages free of package prefixes.
- **I/O only through ports.** `Runner` (git and ssh, 10 s timeout), `NeutralDirs`, `ProfileResolver`, `ProviderSource`. The only files exec writes are the two neutral directories and the stub, with mode 0700 checked on an opened descriptor; it never changes a directory it did not create.
- **Not a security boundary** (brief §10): `env -i`, `git -c credential.helper=`, an SSH URL typed by the agent, and a later `.netrc` are documented bypasses.
- **Tests** call `testenv.Isolate(t)` first. The process tests in `cmd/agent-id/exec_test.go` are the isolation test of #20: fake HOME, recording helper, fake `hosts.yml`, fake tokens, never the real ones.
- **`env` renders the same pipeline as shell text** (#26): `Render` is pure, chains every statement with `&&`, single-quotes every value, never prints a name that fails `^[A-Za-z_][A-Za-z0-9_]*$` or a value that looks like a secret (`ErrUnrenderable`), and moves the shim directory first on `PATH` relative to the shell's own `$PATH`. `Plan.Unshadow` (`git` and the provider's CLI) affects only rendering. Slices `exec` and `env` and the `internal/integration/claude` slice call `Activate`; none imports another.
- **Shell hook for functions and aliases** (#135). `shellhook.go` writes the files that `ZDOTDIR`, `BASH_ENV`, and `CLAUDE_ENV_FILE` name, into the private `shell-hook` directory (`ensureFile`, `0600`, under the same `flock` as the #98 hook). `exec` only: `PlanFor` sets them when the mechanism is `exec`. Each file runs the developer's own file first, then `unset -f` and `unalias` for `git` and the provider's CLI. `CLAUDE_ENV_FILE` is a file for each exec, `shell-hook/sessions/<pid>.<random>/claude-env.sh` (`EnsureSession`, `O_EXCL|O_NOFOLLOW`, `0600`; never shared, never rewritten; the next exec sweeps dead-pid and 30-day-old directories; a nested exec sources the outer file). It is the one that works in Claude Code (it runs after the snapshot of functions); `ZDOTDIR` and `BASH_ENV` serve plain shells. The developer's own values live in `AGENT_ID_USER_ZDOTDIR`, `AGENT_ID_USER_BASH_ENV`, and `AGENT_ID_USER_CLAUDE_ENV_FILE`, which `validSetName` allows; re-entry reads them, never agent-id's own files. Never write the developer's start files or `~/.claude`. Ask first before changing a name. `TestExecNeutralizes*` in `cmd/agent-id/shellfn_test.go` run real zsh and bash.
- **Compare URLs as Git does** (#100). `urlmatch.go` normalizes `http.<url>.*` patterns and URLs like Git's `urlmatch.c`: never decode the path, keep the query and fragment in it, escape unsafe bytes. Never use `net/url` for this. A form the matcher cannot predict is unparsable: a non-empty header with such a pattern is refused, an empty reset with such a pattern is ignored. A change to `urlmatch.go` must keep `TestUrlmatchAgreesWithGit` and `TestRealGitSendsWhatTheCheckPredicts` green; they run real Git.
- **The header check is linear in practice** (#108). `headers.go` parses each `http.<url>.extraheader` pattern once (`compileHeaderRules`) and indexes the rules by host, scheme, port and path. `TestIndexedHeadersAgreeWithTheReference` compares it with the old evaluation on random sets; keep it green. The check also covers `http://<host>/` (#107): the baseline resets only the https form, so a generic header is refused unless the configuration resets the http form too.

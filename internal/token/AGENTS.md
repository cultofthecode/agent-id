# internal/token

The token manager (#18): caches provider tokens on disk, one entry per key, and refreshes them before they expire. The contract is `.ai/specs/2026-11-13-token-manager.md`; the requirements are in `.ai/specs/capabilities/token-cache.md`. Every change here is `risk-high` (credential handling, `SDLC.md`).

- **Core only.** Imports `internal/provider` and the standard library, nothing else of this repository (depguard `token-uses-only-the-provider-port`, a strict allow-list; tests may also import `providertest` and `testenv`). It knows no forge: the key is provider name, host, `TokenSubject()`, and scope (`full` in the MVP). Never parse a token or test its prefix here.
- **Fail closed.** `Manager.Token` returns a token only when it stays valid for longer than the margin (default 5 min). A failed mint wraps the provider error and never serves the old entry; a minted token within the margin is `ErrUnusableToken`; a failed cache write is `ErrCacheWrite` and discards the token. No retry, no backoff.
- **On disk.** `Manager.Dir` is absolute and is cleaned once; only the cleaned path is checked and used (`Dir(os.Getenv)`: `$XDG_CACHE_HOME/agent-id/tokens`, default `~/.cache/agent-id/tokens`). The directory is `0700`, owned by the user, not a symlink; its parent is the user's and not group- or other-writable; otherwise `ErrInsecureCache`, and nothing is `chmod`ed. Entries are `<sha256>.json`, mode exactly `0600`, read with `O_NOFOLLOW|O_NONBLOCK` and checked on the descriptor, at most 64 KiB, strict JSON with the key stored and compared. Anything wrong with an entry is a miss and the entry is replaced. Writes remove the entry's stale temporary files (under its lock), then go to a `0600` temporary file `<sha256>.json.*.tmp`, `fsync`, `rename`, and a best-effort directory `fsync`. A directory in place of an entry is `ErrCacheWrite` naming the path; it is never deleted.
- **Locking.** A refresh holds an exclusive `flock` on `<sha256>.lock` (opened with `O_NOFOLLOW`; a symlink, FIFO, or foreign file is `ErrInsecureCache`, any other open failure `ErrCacheWrite`) and re-reads the entry under the lock, so concurrent processes mint once. The wait ends with the context or `LockTimeout` (default 60 s, above the adapter's 30 s HTTP timeout).
- **No secret leaves the package.** No logger. Errors name the key (no secret), paths (hashes only), and the fix; decoding errors are the fixed `errInvalidEntry`, never a parser error. `assertNoToken` checks errors in the tests.
- **One descriptor.** `prepareDir` checks the parent and the directory by path (`Lstat`), opens the directory with `os.OpenRoot`, re-checks the opened descriptor, and requires it to be the directory it checked (`os.SameFile`). Every entry, temporary-file, and lock-file operation and the directory `fsync` go through that `*os.Root`, never through a path (#67). `os.Root` follows a link that stays inside the root even with `O_NOFOLLOW`, so open entries and lock files only through `openNoFollow` (an `Lstat` before and a same-file check after). Create the lock file with `O_EXCL` (`createMissing`): on darwin an `os.Root` open with `O_CREATE` but without `O_EXCL` fails with `ENOENT` under contention.
- **Pure decisions** with hostile-input tables: `KeyFor`, `Key.fileName`, `Dir`, `checkDir`/`checkParent`/`checkRoot`, `usableEntryFile`, `decodeEntry`, `checkValue`, `fresh`, `checkMinted`. Keep new rules there.
- **Tests** call `testenv.Isolate(t)` (through `newManager`), use the clock-relative test `source` or `providertest.Fake`, and seed entries with `encodeEntry`/`writeEntry`. `TestMain` runs `testenv.Main` and the child mode of the 20-process test, which prints token hashes, never tokens. Tests that rely on permissions skip as root.

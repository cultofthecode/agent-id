# internal/token

The token manager (#18): caches provider tokens on disk, one entry per key, and refreshes them before they expire. The contract is `.ai/specs/2026-11-13-token-manager.md`; the requirements are in `.ai/specs/capabilities/token-cache.md`. Every change here is `risk-high` (credential handling, `SDLC.md`).

- **Core only.** Imports `internal/provider` and the standard library, nothing else of this repository (depguard `token-uses-only-the-provider-port`). It knows no forge: the key is provider name, host, `TokenSubject()`, and scope (`full` in the MVP). Never parse a token or test its prefix here.
- **Fail closed.** `Manager.Token` returns a token only when it stays valid for longer than the margin (default 5 min). A failed mint wraps the provider error and never serves the old entry; a minted token within the margin is `ErrUnusableToken`; a failed cache write is `ErrCacheWrite` and discards the token. No retry, no backoff.
- **On disk.** `Manager.Dir` is absolute (`Dir(os.Getenv)`: `$XDG_CACHE_HOME/agent-id/tokens`, default `~/.cache/agent-id/tokens`). The directory is `0700`, owned by the user, not a symlink; its parent is the user's and not group- or other-writable; otherwise `ErrInsecureCache`, and nothing is `chmod`ed. Entries are `<sha256>.json`, mode exactly `0600`, read with `O_NOFOLLOW|O_NONBLOCK` and checked on the descriptor, at most 64 KiB, strict JSON with the key stored and compared. Anything wrong with an entry is a miss and the entry is replaced. Writes go to a `0600` temporary file, `fsync`, `rename`, directory `fsync`.
- **Locking.** A refresh holds an exclusive `flock` on `<sha256>.lock` (opened with `O_NOFOLLOW`; a symlink, FIFO, or foreign file is `ErrInsecureCache`) and re-reads the entry under the lock, so concurrent processes mint once. The wait ends with the context or `LockTimeout` (default 60 s, above the adapter's 30 s HTTP timeout).
- **No secret leaves the package.** No logger. Errors name the key (no secret), paths (hashes only), and the fix; decoding errors are the fixed `errInvalidEntry`, never a parser error. `assertNoToken` checks errors in the tests.
- **Pure decisions** with hostile-input tables: `KeyFor`, `Key.fileName`, `Dir`, `checkDir`/`checkParent`, `usableEntryFile`, `decodeEntry`, `checkValue`, `fresh`, `checkMinted`. Keep new rules there.
- **Tests** call `testenv.Isolate(t)` (through `newManager`), use the clock-relative test `source` or `providertest.Fake`, and seed entries with `encodeEntry`/`writeEntry`. `TestMain` runs `testenv.Main` and the child mode of the 20-process test, which prints token hashes, never tokens. Tests that rely on permissions skip as root.

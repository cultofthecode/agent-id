# internal/provider/github

The GitHub adapter of the provider interface (ADR #35, spec `.ai/specs/2026-11-13-github-provider-adapter.md`, #15). It is the only package with GitHub-specific code: App JWT, installation tokens, the bot user, `api.github.com`, `github.com`, and `gh` wiring. Only `cmd/agent-id` imports it (depguard `github-only-in-its-adapter`, and `TestOnlyTheCompositionRootImportsTheAdapter`); it registers the profile block validator there (#58).

- **Standard library only, written from scratch.** No GitHub client or JWT library, and no GHAPP code (owner decisions on #15; `CODE_REVIEW.md`, Provenance). A new dependency is an "Ask first" item.
- **The key never leaves the process.** `New` parses the PEM once and keeps the `*rsa.PrivateKey`; only signatures go out. `Config` and `Provider` redact the key under every `fmt` verb. No error contains a token, a JWT, key material, a response body, or a transport error's text.
- **Credentials stay on `api.github.com`.** The base URL, HTTP client, and clock are unexported test hooks (`newProvider` with `api`), so production code cannot send the App JWT elsewhere. The client is always copied with redirects off; pages are counted on the fixed base URL and `Link` is never followed.
- **Fail closed, one class per failure.** `classify` maps a status to `ErrUnauthorized` (401), `ErrNotFound` (404), `ErrRateLimited` (429, or 403 with `X-RateLimit-Remaining: 0` or `Retry-After`), `ErrForbidden` (other 403), and `ErrUnavailable` (everything else, transport errors, unusable answers). A canceled context returns the context's error.
- **Answers are hostile input.** A token is accepted only with the `ghs_` prefix, in visible ASCII, at most 4096 bytes; the slug, the bot login, the user type and id, and repository owners and names are checked against fixed patterns; bodies are capped at 1 MiB. Security checks are pure functions (`parsePrivateKey`, `signJWT`, `checkBaseURL`, `classify`, `parseToken`, `CommitIdentity`) with hostile-input tables.
- **Tests** call `testenv.Isolate(t)` first (directly or through the helpers in `helpers_test.go`), use the per-test key of `githubtest.NewApp`, reach only `testenv.NewFakeAPI` through `testenv.NewHTTPClient(t)`, and run `providertest.RunContract` against the adapter. Hostile answers come from custom routes on a `testenv.FakeAPI`.
- **The `github` profile block** (`settings.go`, #58) is owned here: `DecodeProfileSettings` is strict (members in document order, unknown and missing members refused, IDs as JSON integers 1…2⁵³−1, `private_key` through `profile.ParseKeyRef`, `identity` complete or absent, login `<slug>[bot]`, `resolved_at` RFC 3339 UTC), only `host: github.com` passes, and errors come from `profile.Errorf`, start with `host:` or `github.…`, and never echo the key reference. `MarshalJSON` refuses what the decoder refuses. `Update` drops a carried-over identity when the host or the App ID changes. `ProfileRegistration` hands the validator and `TokenPrefixes` to the composition root.

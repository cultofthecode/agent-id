# The `gh` shim: a fresh bot token for every `gh` call in an agent context

Extends: `.ai/specs/2026-11-13-exec-child-environment.md` (the neutral credential baseline of #68 and the `PathPrepend` and `Set` rows that name #23)

Issue: #23 (E02-S09). Inputs: the decision comment of the project manager on #23, the analysis `.ai/analysis/2026-11-12-gh-installation-token-matrix.md` (#14, PR #34), PR #40, ADR #35.

## TLDR

Inside `agent-id exec`, `gh` is a refusing stub. This spec replaces the stub with a shim. The shim is a small script that starts a hidden subcommand, `agent-id cli gh`. That subcommand checks the arguments, takes a token from the token manager, and replaces itself with the real `gh`. The real `gh` gets a fresh token in `GH_TOKEN` for that one call. The token is never in the environment of the agent that called `gh`, never in output, and never on disk outside the token cache. Programs that `gh` itself starts inherit it (OQ5).

## Decisions (from the issue, #34 and #40)

| # | Decision | Source |
|---|---|---|
| D1 | In agent mode `gh` runs with the empty agent-id `GH_CONFIG_DIR`. The shim sets it on every call. | #23 decision comment |
| D2 | `gh` never runs with an empty token. No token means no `gh`. | #23 decision comment, #40 |
| D3 | A deny-list of user-centric commands. It can become an allow-list later. | #23 decision comment |
| D4 | A refused command exits non-zero with a message that holds no secret. | #23 decision comment |
| D5 | A host other than the profile's host is refused, in arguments and in `GH_REPO`. | #23 decision comment |
| D6 | The shim takes its tokens from `internal/token`. It mints nothing itself. | task |

Not decided here, and not guessed: the exit code. The comment says "non-zero". This spec uses **125**, the code that `exec` uses for "agent-id failed before the command started". See OQ1.

## Design

### Parts

| Part | Package | Owns |
|---|---|---|
| Launcher | `internal/activation` (`neutral.go`) | The content of `<cache>/agent-id/<provider>/neutral-bin/<binary>`. It replaces the refusing stub. It is still a self-contained script, so a removed binary cannot let the shell fall through to the real `gh`. |
| Slice | `internal/cliint` | `contract.go`, `handler.go`, `command.go`. Finds the real CLI, checks the arguments, gets the token, builds the environment, replaces the process. Names no forge. |
| Rules | `internal/provider` (`CheckCLI`) and `internal/provider/github` | The deny-list and the host check. They live in the adapter because the command names are GitHub's. |
| Wiring | `cmd/agent-id/main.go` | Builds the handler from the profile store, the adapter, `token.Manager`, and `activation.FileNeutralDirs`. |

### The launcher

```sh
#!/bin/sh
if [ -n "${AGENT_ID_BIN:-}" ] && [ -x "$AGENT_ID_BIN" ]; then
  exec "$AGENT_ID_BIN" cli gh -- "$@"
fi
printf '%s\n' 'agent-id: AID-GH-TOKEN: ...' >&2
exit 125
```

`AGENT_ID_BIN` is the variable that `exec` already sets. The script has no token and no profile. The binary name is a fixed identifier (`^[a-z][a-z0-9-]{0,31}$`) checked by `Ensure`. When the binary is missing, the launcher refuses with exit 125. It never starts the real CLI.

### `agent-id cli <binary> [--] [args…]`

A hidden command. Flags are not parsed: every argument after `--` goes to the CLI as it is.

Order of steps. Each step fails closed, and no step before the last one starts the CLI.

1. **Context.** `ReadContext(parent)` must return a context. No context means refusal: the shim works only inside an agent context. The profile is the context's profile.
2. **Binary.** `<binary>` must equal the provider's `NeutralCLI().Binary`.
3. **Recursion.** A refusal when the marker variable `AGENT_ID_CLI_ACTIVE` is set in the parent (a CLI that started `gh` through `PATH`).
4. **Rules.** `Activator.CheckCLI(args, parent)`. A `*provider.CLIRefusal` ends the run with its message. Nothing was read from the key store and no token was requested.
5. **Neutral directories.** Prepare them as `exec` does (`FileNeutralDirs.Ensure`). This also rewrites the launcher when its content differs, and it refuses a `hosts.yml` in the configuration directory.
6. **Real CLI.** Walk `PATH` of the parent. Skip an entry that is not an absolute directory, the launcher's directory, and any file that is the same file as the launcher (`os.SameFile`). The first executable regular file wins. None found: `NOCLI`. Only links to the launcher: `LOOP`.
7. **Token.** Check `Activator.Ready()`, open the provider for the profile (this loads the key), and call `token.Manager.Token`. Any error is a refusal `AID-<CLI>-TOKEN`. A token with an empty value is a refusal too (D2).
8. **Environment of the CLI.** Start from the parent. Remove the provider's `CredentialVariables`. Set the provider's decoys again (they keep the other host closed). Set the variables of `Provider.CLIEnvironment(token)` (GitHub: `GH_TOKEN`, `GH_HOST=github.com`). Set the configuration directory variable to the neutral directory (D1). Add `AGENT_ID_CLI_ACTIVE=1`.
9. **Replace.** `execve` the real CLI with this environment. Exit status and signals are the CLI's. agent-id prints nothing.

### Refusals

One line on stderr: `agent-id: <CODE>: <message>`. Exit 125. No message holds a token, a header, key content, a URL user-info, or the parent's variable values. A message from the key loader can name the key file path, so that the developer can fix its mode. The reason of a token failure is a fixed phrase for each known error class, and `an unexpected failure` for any other error. Text from the profile, the key, or the neutral directories passes `Scrub`: when it holds a token prefix, a PEM marker, a JWT shape, or a control character, the reason becomes `details withheld`.

| Code | When | Owner |
|---|---|---|
| `AID-GH-TOKEN` | The token cannot be obtained, is empty, or the profile or key cannot be opened | `cliint` |
| `AID-GH-NOCLI` | No real `gh` on `PATH`, or only the launcher | `cliint` |
| `AID-GH-LOOP` | The marker is set, or the real CLI is the launcher | `cliint` |
| `AID-GH-CONTEXT` | No valid agent context, or a binary name that is not the provider's | `cliint` |
| `AID-GH-AUTH` | Any `gh auth …` | adapter |
| `AID-GH-USER` | A command that needs a user account | adapter |
| `AID-GH-ME` | `@me`, or a repository name without an owner | adapter |
| `AID-GH-HOST` | Another host in an argument, in `GH_REPO`, or in a URL | adapter |

The code prefix of the first four is `AID-` + upper-case CLI name + `-`, so `cliint` names no forge.

### The GitHub rules (`internal/provider/github/cli.go`)

The input is the argument list and the parent environment. The function is pure.

- **Leading arguments.** The first argument decides. `--help`, `-h`, `--version`, and `help …` pass. Any other argument that starts with `-` is refused (`AID-GH-USER`, "unsupported option before the command"): `gh` takes no other global option, so this closes a parse trick.
- **`auth`.** Refused with any subcommand and without one (`AID-GH-AUTH`). That covers `login`, `logout`, `switch`, `refresh`, `setup-git`, `status`, `token`, and `git-credential`.
- **User commands** (`AID-GH-USER`): `status`, `gist`, `org`, `ssh-key`, `gpg-key`, `codespace`, `cs`, `agent-task`, `agent-tasks`, `agent`, `agents`, `gists`, `extension`, `extensions`, `ext`, `repo create`, `repo new`, `repo fork`, `repo list` and `repo ls` without an owner argument.
- **Configuration commands** (`AID-GH-USER`): `alias` and `config`, with any subcommand. An alias such as `auth token` would run with the bot token after the shim checked only the alias name. A `pager`, `browser`, or `editor` setting would start a program of the agent's choice with the token. `gh` keeps both in `config.yml` of the neutral directory, so a stored value would also outlive the call. The agent can still run the real `gh` by absolute path, where `alias set` and `config set` work and write `config.yml` into that directory. So the GitHub adapter's `NeutralCLI().ForbiddenConfigFiles` lists `config.yml` as well as `hosts.yml`: `exec` and the shim refuse to start while the file exists (`gh` never creates it by itself for any other command), and the message tells the developer to remove it. This is a check at the next start, not a boundary.
- **User endpoints** (`AID-GH-USER`): `api` with an endpoint that is `user`, `user/…`, `app`, or `app/…`, with or without a leading `/`. `users/<name>` passes. Query strings, percent-encoding (decoded up to three times), and dot segments do not hide the path. Case does not matter.
- **`@me`** (`AID-GH-ME`): any argument that is `@me`, ends with `=@me`, or has `@me` as a comma-separated item. `repo view NAME` and `repo clone NAME` with a name that has no `/` and is not a URL.
- **Host** (`AID-GH-HOST`):
  - `--hostname VALUE` and `--hostname=VALUE`.
  - `-R VALUE`, `--repo VALUE`, `--repo=VALUE`, `-RVALUE`, and `GH_REPO`: `HOST/OWNER/REPO` with three parts, or a URL.
  - Any argument that is a URL (`scheme://…`) or starts with `//`.
  - Any argument shaped `HOST/OWNER/REPO` where `HOST` has a dot and holds only letters, digits, `_`, `.`, `-`. The scp form `[user@]host:path`, in the same places. A short flag cluster that holds `R`, for example `-wRhost/o/r`.

  - The allowed hosts are the profile host, `api.<host>`, and `uploads.<host>`, case-insensitive. A host with a port, a user-info, a trailing dot, or a Unicode letter is refused.

Everything else passes. The deny-list is a first version (D3).

### What the neutral baseline keeps

The decoy `GH_TOKEN` and the empty `GH_CONFIG_DIR` stay in the child environment of `exec`. A `gh` started by absolute path, or through a `PATH` that a startup file rewrote, still reaches the decoy and never the keychain. The shim adds the bot token only for the call that passed every check.

### Removed and kept

- `exec` still sets no token. The agent's environment holds the decoy only.
- Nothing is written to `hosts.yml`, the developer's `gh` configuration, the keychain, or `~/.gitconfig`.
- `GH_DEBUG=api` output is masked by `gh` for `Authorization`; the shim does not print.

## Open questions

- **OQ1 Exit code.** 125 for every refusal, as for `exec`. A separate code per class is possible. Recommendation: keep 125, because the stderr line starts with the code `AID-GH-…` and scripts can match it.
- **OQ2 Marker variable.** The shim sets `AGENT_ID_CLI_ACTIVE=1` for the real CLI. It is a new variable name, but `exec` and `env` do not emit it. Recommendation: accept; it only guards recursion.
- **OQ3 Real CLI by `PATH`.** The shim finds the real `gh` at call time. An agent can put its own `gh` earlier on `PATH` and receive a token (documented bypass, brief §10). Recording a path at `exec` time would need a new variable. Recommendation: keep call-time lookup; local mode is not a boundary.
- **OQ5 Inherited token.** The pager, browser, editor, `git`, and installed `gh` extensions that `gh` starts inherit the bot token in their environment. An agent can choose them with `GH_PAGER`, `GH_BROWSER`, `GH_EDITOR`, or a file in `$XDG_DATA_HOME/gh/extensions`, and read the token in its own program. Recommendation: accept for the first version, because the agent already runs as the same user and the token lives about one hour. Stripping the pager, browser, and editor variables is an owner decision.
- **OQ4 `auth git-credential`.** Refused with all of `auth`. Git never calls it in agent mode, because #22 resets the helpers.

## Test plan

Hostile-input tables for `CheckCLI`, `Scrub`, the real-CLI lookup, and the environment builder. In-process handler tests with `providertest.Fake` for the mint failures (`ErrUnauthorized`, `ErrForbidden`, `ErrNotFound`, `ErrUnavailable`, `ErrRateLimited`, an empty token, an unusable token) and for two calls across a refresh. Process tests in `cmd/agent-id` with a fake `gh` that prints the SHA-256 of `GH_TOKEN`: two calls get two current tokens; a personal `GH_TOKEN` and `GITHUB_TOKEN` never reach the fake; every deny-listed class exits 125 with zero calls; a launcher that finds itself fails instead of looping; the #25 scenarios for `gh` (broken key states) end in `AID-GH-TOKEN` with no personal use. All tests call `testenv.Isolate(t)`; the tokens are `ghs_aidtest_…`; the fake GitHub is the only host.
